# Security policy

## Supported versions

Threads of Gold has not released a production version. Security corrections are
currently applied to `main`. Repository administrators must keep required
security checks and review protections enabled before production use. A
supported-version table will be added when the first staging release is tagged.

## Reporting a vulnerability

Use GitHub private vulnerability reporting for this repository. Include the
affected route or component, impact, reproducible steps, and any suggested
mitigation. Do not include customer information, payment data, credentials, or
active secrets in a report.

Do not disclose an unresolved vulnerability in a public issue or discussion. If
private vulnerability reporting is unavailable, open a minimal public issue
asking for a private contact channel without including exploit details.

The maintainer will acknowledge a report, assess severity and affected versions,
coordinate a correction, and communicate a disclosure decision. Response times
remain best-effort until the production support and incident objectives are
approved.

## Scope boundaries

The current account, checkout, order, and payment behavior is prototype or
foundation behavior. It must not be used for real customer data or payments.
That boundary does not make security findings irrelevant; vulnerabilities in the
prototype or engineering foundation should still be reported privately.
